## 3. Output Tokens & Layer-2 Compression

Output tokens are a small share of total volume (~0.4%) but are billed at a **premium multiplier** vs cached input. That makes output compression disproportionately valuable at scale.

### What each scenario compresses

| Capability | Claude (normal) | Claude + RTK | Claude + Edgee |
|---|---|---|---|
| Bash / tool-result trimming (Layer 1 input) | — | ✅ (sole focus) | ✅ `tool_result_trimming` |
| Tool-surface reduction (Layer 1 input) | — | — | ✅ `tool_surface_reduction` |
| Model response brevity (Layer 2 output) | — | — | ✅ `output_brevity` |

**RTK is one technique** — it filters terminal/bash output before it enters context (analogous to Edgee's `tool_result_trimming`). It does **not** trim the tools list or compress what the model writes back.

**Edgee runs three composable strategies** on the gateway: two Layer-1 input compressors plus **`output_brevity`**, which constrains model responses (filler, scaffolding, over-explanation) on the return path. This benchmark's output-token gap is where that third lever shows up.

## 4. Cache Efficiency

Cache efficiency is assessed via two ratios:
- **Cache Read Ratio** = `cacheReadTokens / (cacheReadTokens + totalInputTokens)` — how much of input came from cache
- **Cache Write Overhead** = `cacheCreationTokens / totalOutputTokens` — cost of warming the cache relative to generation

| Label | Cache Read Tokens | Cache Read Ratio | Cache Creation Tokens | Creation/Output Ratio |
|---|---|---|---|---|
| Claude | 13,604,254 | 99.90% | 364,156 | 7.02x |
| Claude + RTK | 12,777,733 | 99.95% | 529,752 | 7.97x |
| Claude + Edgee | 10,116,351 | 99.81% | 241,014 | 6.49x |

**Key observations:**
- All three scenarios show **exceptional cache read ratios (>99.8%)**, meaning the vast majority of input is served from cache — the caching strategy is working well across the board.
- **Claude + RTK** achieves the highest cache read ratio (99.95%) with the fewest fresh input tokens, making it the most cache-read-efficient per call.
- **Claude + Edgee** has the lowest cache creation overhead, meaning it writes less into the cache relative to its output — the most cache-write-efficient scenario.
- **Claude (normal)** falls in the middle on both metrics.
